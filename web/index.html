How Scafonix 2-of-2 Programmable MPC Vault Works:
Standard wallets use a single private key that can be drained if leaked. Scafonix Vault splits your key into 2-of-2 MPC shares: you hold Share A, and the automated Inspector holds Share B (co-signing only when your AWS IAM JSON policy allows it).

  • Step 2 (Generate Vault & Set Rules): Need a new vault or custom policy? Define your AWS IAM JSON rules on Tab 2 and execute 2-party DKG.
  • Step 3 (Emergency Rescue): If the server ever goes offline, use your encrypted Share C voucher on Tab 3 for 100% unilateral recovery.

AWS IAM Policy Syntax Specification & Guide (Click to expand)

scafonix Vault policies follow an AWS IAM-style JSON specification. During signature requests, the automated Inspector evaluates every statement against the proposed transaction parameters.

1. Evaluation Rules (Allow vs. Deny):
  • Default Deny: By default, all transactions are denied. A transaction is only approved if at least one statement with "Effect": "Allow" matches.
  • Explicit Deny Precedence: If any statement with "Effect": "Deny" matches the transaction, the transaction is immediately denied, regardless of any matching Allow statements.

3. Practical Use Cases & Examples:
• Budget Spending Cap: Allow transfers up to 0.1 ETH per tx on Mainnet.
• DEX Router Whitelisting: Allow contract calls exclusively to Uniswap V3 SwapRouter.
• Dedicated Cold Storage: Allow transfers only to a single whitelisted cold wallet address.
• Multi-Address Whitelist: Allow transfers to multiple trusted addresses across any chain.
• Contract Lockdown (Anti-Drainer): Explicitly Deny all web3:CallContract transactions to protect against malicious approvals.
